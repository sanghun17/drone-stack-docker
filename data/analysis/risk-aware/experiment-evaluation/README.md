# Repeated simulation analysis

The runtime runner saves raw evidence under `flight_logs/<batch>/iter_NNN`.
`metrics.csv` is the online map metric log; it is **not** a drop-in replacement
for historical cherry-pick `experiment_metrics.csv` (`SurfaceRateGT` is absent).

Export each completed trial in the comparison ROS environment:

```bash
docker exec drone-stack-sim-x86 bash -c '
  source /opt/ros/noetic/setup.bash
  source /work/ws/risk-aware-comparison/devel/setup.bash
  python3 /work/data/analysis/risk-aware/experiment-evaluation/export_legacy.py \
    /work/flight_logs/BATCH/iter_001 \
    --output /work/data/results/BATCH/iter_001
'
```

Output directories must be new. Raw bags and historical evidence are unchanged.

- `experiment_metrics.csv`: historical header and units row; 5 s cadence;
  GT/VIO positions, `SurfaceRateVio`, `VolumeRateVio`, `VolumeM3`, `SurfaceRateGT`.
- `gt_vs_vio.csv`: historical dense GT timestamps with interpolated VIO and
  position error, generated by the same legacy helper.
- `endpoint.csv`: historical time/type/reason format. A recorded collision takes
  precedence over the runner's stop label. Both AirSim collision topic names
  are recognized. Other labels come from the explicit runtime result.
- `analysis_metadata.json`: last pre-endpoint GT/VIO positions and their sample
  times, final bag positions, time origin, takeover time, sensor extrinsics,
  source paths, topic counts, GT hash and exporter hash.

`RosTime` is relative to the first relevant bag message, as in the historical
exporter. Runtime `elapsed_s` starts at control takeover; these two zero points
are deliberately recorded separately. `WallTime` repeats `RosTime`, matching
the historical offline exporter, and is not a measured wall-clock duration.
The bag includes the pending-control and shutdown intervals. Clip plots and
aggregates to `endpoint.csv` before comparing flight outcomes. Endpoint location
is the last dense sample at or before the event, not a 5-second metric row.

`SurfaceRateGT` accumulates `/voxel_grid/output` sensor clouds transformed by
the latest GT pose and the historical camera extrinsic, then intersects the GT
voxel set. It does not use the drifting planner map. The RHEM map rates expand
OctoMap leaves onto the shared grid and use the same `eval_core.compute` as
LA/PURE. Do not relabel `SurfaceRateVio` as `SurfaceRateGT`.

On 2026-09-22 the first collision-fixed RHEM trial was independently processed
by the original `ExperimentPlotter._process_iteration_bag`: all GT surface
rates and sample times agreed within 1e-6, and dense `gt_vs_vio.csv` matched
byte-for-byte. Evidence is in the batch's `legacy-verification` result folder
and `flight_logs/rhem-vio-10-20260922-host/legacy-verification.log`.

The earlier `flight_logs/rhem-vio-10-20260922` batch is diagnostic only: its
runner missed `/collision` and incorrectly ran two trials to 300 s. The bags
preserve actual collision events. The corrected batch is
`flight_logs/rhem-vio-10-20260922-collision-fixed`. Do not pool the old two
runs with the corrected ten or interpret their `time_limit` labels as
collision-free flight. A third setup was interrupted before recording.

After exporting all trials, generate a batch table and static figure:

```bash
python3 data/analysis/risk-aware/experiment-evaluation/summarize_batch.py \
  data/results/BATCH --raw-batch flight_logs/BATCH
```

This writes `batch_analysis.csv` and `coverage_and_endpoints.{png,pdf}`.
The table's `surface_gt_last_pre_endpoint` is the last **5-second sample**
preceding the endpoint, not an interpolated value at impact. Its sample time
is included. Position differences use the separately timestamped last GT/VIO
samples; dense synchronized errors are available in `gt_vs_vio.csv`.

For new batches, the host entrypoint
`stacks/sim-x86/scripts/run_evaluated_experiments.sh` accepts the same arguments
as `run_experiments.sh` and requires `--output /work/flight_logs/BATCH`.
It runs recording, exports recorded trials, retaining invalid-evaluation labels to `data/results/BATCH`,
then generates the summary CSV and figure automatically. It refuses existing
raw or analysis destinations. `pipeline_status.json` in the raw batch records
runner/export exit codes; `export_status.json` records the requested count and
exported/skipped trials. All attempted trials remain in `trial_outcomes.json`, including failed or
unexportable trials. Completion of 100 attempts is distinct from 100 valid
evaluations or mission successes. An individual export error is recorded and
does not prevent exporting the remaining trials.

Before each trial the runner removes unreachable `/rhem/` ROS registrations.
This prevents stale XMLRPC ports from sending a duplicate-name shutdown to an
unrelated new trial process. Reachable RHEM and unrelated nodes are preserved.


## Resuming the 100-trial run (2026-09-23)

`--resume-from /work/flight_logs/OLD_BATCH --iterations 100` creates a new
output batch with relative links to the already completed trial directories,
then starts at the next index. Source/control choices and timing settings must
match. Existing records must agree with the prior summary and have clean
teardown. Old records and their original provenance are not overwritten.
The new manifest identifies `resume_from` and snapshots the new runner.

The 2026-09-22 batch stopped at trial 28 because `belief_not_ready` was treated
as a batch-level error despite successful recording and cleanup. The resumed
batch is `rhem-vio-100-20260923-resumed`, with trials 1–28 preserved and new
trials beginning at 29. The readiness gate is unchanged; failures are retained
with `valid_evaluation=false`, not discarded or converted to success.

A detached `supervise_experiment_campaign.py` monitors the active batch and
writes `flight_logs/rhem-vio-100-20260923-host/campaign_status.json` every 10 s.
If a partial batch has exited with clean teardown, it launches a new output
with `--resume-from` and the original target of 100. It does not retry an
explicit interruption or cleanup failure. The status distinguishes completed
attempts, valid evaluations, full completion, and analysis failure. The first
resumed process was started with the belief-failure continuation fix; subsequent
restarts also use the generalized per-trial-exception continuation policy.
