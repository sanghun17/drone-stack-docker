# Orchestration 규칙 — 메인 에이전트는 지휘, 실행은 위임

메인 에이전트는 **오케스트레이터**다. 역할은 계획 수립, 작업 분해·분배, 중요한 결정, 결과 검증·종합이며, 실제 구현은 서브 에이전트에게 위임한다.

## 메인 에이전트가 직접 처리하는 것

- 1~2개 파일의 작은 수정 (합계 ~50줄 미만)
- 오타 수정
- 설정 변경 (yaml / launch / json / module.yml 등)
- 문서 수정 (md 등)
- 단순 질문·조회 (파일 1~2개 읽어서 답할 수 있는 것)

## 서브 에이전트에 위임하는 것

- 새 기능 구현
- 3개 이상 파일 변경
- 50줄 이상 코드 변경이 예상되는 작업
- 테스트 코드 작성
- 리팩토링

## 라우팅

| 에이전트 | 모델 | 담당 |
|---|---|---|
| `deep-reasoner` | Opus | 무거운 추론: 아키텍처/알고리즘 설계, 원인 불명의 파이프라인·제어 이슈 진단, 트레이드오프 비교 |
| `default-worker` | Sonnet | 일반 구현: 기능 구현, 다파일 변경, 테스트 작성, 리팩토링 |
| `task-worker` | Haiku | 잡무: 파일 이동/rename, 로그 수집, 검색·조사, 포맷 정리 |

위임 시 원칙:
- 프롬프트에 **명세를 완결적으로** 담는다: 대상 파일, 기대 동작, 검증 방법, 하지 말 것. 서브 에이전트는 대화 맥락을 못 본다.
- 독립적인 작업들은 **한 메시지에 여러 Agent 호출**로 병렬 실행한다.
- 서브 에이전트 결과는 그대로 믿지 말고 diff/핵심 지점을 직접 확인한 뒤 종합해서 사용자에게 보고한다.
- 설계가 갈리는 결정은 위임하지 않는다 — 메인 에이전트가 결정하고, 결정된 명세를 위임한다.

## 강제 장치 (orchestration-gate 훅)

`.claude/hooks/orchestration-gate.sh`가 PreToolUse 훅으로 등록되어 있다:
- **메인 에이전트**는 한 턴(사용자 메시지 1개)당 **코드 파일 2개까지만** Edit/Write할 수 있고, 3개째부터는 차단된다.
- 서브 에이전트의 수정은 제한 없음 (`agent_id`/`agent_type` 필드로 구분).
- 코드 파일 판정: py, c/cc/cpp/h/hpp, cu/cuh, js/ts/jsx/tsx, sh/bash/zsh, go, rs, java, kt, proto, cmake, CMakeLists.txt, ipynb. yaml/json/launch/md 등 설정·문서는 제한에 안 걸림.
- 차단당하면 파일을 쪼개서 우회하지 말고, 그 시점에서 작업을 `default-worker`(또는 필요시 `deep-reasoner`)에게 위임할 것.
