# FAST-LIVO multi-flight robustness campaign (2026-08-03)

## Outcome

The promoted configuration completed all nine selected camera + point-cloud +
IMU + VRPN flight bags at real-time replay rate with **0/9 catastrophic
divergences**.  Seven of nine also pass the stricter secondary trajectory
integrity gate.  The remaining accuracy limitations are `02-21-43` and
`03-43-50`; neither diverges catastrophically, but their estimated path length
is more than 2x the associated VRPN path.

Catastrophic is pre-defined as translation APE exceeding twice the full VRPN
path length.  Scoring uses no spatial alignment.  A run cannot pass by dying or
freezing: coverage must be at least 95%, largest output gap at most 0.5 s,
output/input ratio at least 0.9, and estimated/GT associated path ratio in
`[0.5, 2.0]` for the secondary `valid` flag.

## What was found

1. The original full LIVO baseline catastrophically diverged on 8/9 bags.
   Coverage and output counts were still about 99%, so simple CPU overload or
   dropped frames did not explain the failures.
2. Failure has two observable forms:
   - visual updates sometimes operate on only 1--20 patches and make large
     pose corrections;
   - LiDAR effective point-plane support can collapse from roughly 1,000 to
     10--20, after which unchecked IMU propagation turns a small tilt error
     into unbounded translation.
3. IMU axes/sign, factory IMU-depth rotation, and a gross time-offset error
   were excluded.  The configured extrinsic was within about 1.8 degrees of
   the GT-derived optimum; the best timing shift was about -15 ms.
4. Always-on VIO and LIO-only have complementary failure/accuracy profiles.
   In particular VIO greatly helps LiDAR-weak `02-56-57`, but inflates paths on
   several LiDAR-strong flights.
5. A VIO photometric inlier threshold does not solve the problem.  Per-frame
   GT-benefit Spearman correlations for inlier ratio, error ratio, VIO/LIO
   information eigenvalue ratios, support, and correction size are all weak
   (absolute correlation below about 0.1).  A global scalar quality gate is not
   supported by the data.
6. A rotation-only visual Jacobian was explicitly tested and rejected.  On
   `00-04-39` it destabilized attitude, caused consecutive LIO rejects, and the
   node eventually segfaulted.  It is not a promoted mode.
7. The useful transferable signal is the immediately preceding **LIO support**.
   Keeping visual tracking/reference maintenance active but allowing visual
   EKF correction only when LIO has at most 50 effective features preserves
   the `02-56-57` benefit while avoiding most always-on VIO path inflation.

## Promoted implementation

- A runtime-disabled-by-default estimator health guard rejects non-finite,
  low-support, excessive correction, speed/step, and vehicle-tilt states.  It
  rolls a bad measurement back to propagation/last trust and holds translation
  after persistent loss of observation.
- `vio.max_lio_features_for_fusion: 50` gates only the visual EKF correction.
  RGB tracking and visual map/reference updates continue on every image.
- The VIO scalar objective is summed deterministically in double precision
  before its accept/rollback branch.
- LIO/VIO observability diagnostics are available in the optional fusion CSV.
- `imu.b_acc_cov` and `imu.b_gyr_cov` are now actually read from YAML.  They are
  set to `0.0001`, the historical hard-coded runtime value used by this
  campaign.  The former YAML value `0.0005` had not been applied by C++.
- Sensor-epoch poses now use `last_lio_update_time` instead of callback
  completion `ros::Time::now()`.  In direct bag inspection, output stamps match
  source image stamps exactly (median and maximum absolute difference 0 s).
- The replay harness clears all FAST-LIVO global ROS parameter namespaces
  before each run and saves a full `<output>_params.yaml` snapshot.  Runs made
  before this cleanup are listed in `_campaign_20260803/INVALIDATED_RUNS.md`.
- Offline replay on the ML x86 workspace no longer depends on the arm64 deploy
  container and does not use global `pkill`, so isolated campaign workers do
  not kill one another.

  --group all \

  --rate 1.0 \
  --force

required.  Use `--ids 02-21-43 03-43-50` for targeted worst-case repeats.

## Remaining work / surrender conditions

- Safety objective: achieved on the selected data (0/9 at 1.0x, 0/12 critical
  repeats at 0.5x).
- Accuracy objective: not complete.  Do not claim completion while
  `02-21-43` and `03-43-50` exceed motion ratio 2.0.
- Do not add another global VIO quality threshold without a development-split
  predictor that separates beneficial from harmful corrections.
- Do not tune further on the locked five validation bags.  A new fusion rule
  requires a new development hypothesis or additional held-out flights.
- The campaign is offline ML validation.  A native Jetson build/live flight was
  not part of this task and is still required before treating the change as a
  flight release.
